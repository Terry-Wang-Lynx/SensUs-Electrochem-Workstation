# USB–RS485 串口变化恢复

2026-10-24：USB 位置变化后，系统端口从 `/dev/cu.usbserial-110` 变成 `/dev/cu.usbserial-1110`。旧流程始终尝试保存的旧路径，并把串口尚未打开时的失败误判为物理停止未知，因此陷入不能修改连接的恢复锁。

当前行为：

- 驱动保存本对象生命周期内的 `serial_opened_once` 证据。只有首次连接从未打开串口、且控制器事先没有任何未完成输出所有权时，才将失败报告为 `motion_port_unavailable`，不虚构停止未知。打开后读取失败、既有实验掉线和历史恢复义务仍严格保留。
- 点击“重连并重置”时，若旧端口已经消失，页面枚举当前串口。明确选择或仅发现一个 USB 候选时仍须确认它是原 X/Z 总线；不将同型号转接器自动当成同一台设备。
- `POST /api/automation/v1/motion/reset` 可提交 `{"port":"新端口","same_bus_confirmed":true}`。仅旧连接已断开、旧端口不再存在、新端口在系统枚举中、没有活动任务时接受；波特率、轴地址和机械配置保持原样。
- 新连接先读取驱动身份/配置并核对已知旧资料，然后双轴 STOP 与新鲜静止反馈确认。成功前保留旧点位及恢复所有权；成功后清除四点授权、保存新端口，再按正常流程确认全部其他输出。某板仍停止未知时不因电机已停而清除全局恢复锁。
- 旧观察线程先撤销并结束，采用新连接前复核旧停止代际，避免迟到停止请求被恢复结果覆盖。任何失败不启动使能或运动。

本次 193 项针对性回归通过；额外覆盖了完整复位、换口、已打开后的失败、历史恢复义务、板卡停止未确认与外部 STOP 竞态。实机已在新端口确认 X1/Z2、双轴 0 RPM、停止确认、故障解除，未发使能、位移、回零或清零命令；保留恢复前后状态和总线审计于 `artifacts/port-recovery-20261024/`。

旧后台因未打开的失效串口而拒绝正常退出，本次维护重启前核实没有串口描述符、采集子进程、活动标定或实验；保留原“停止未知”持久记录，再由新版在新串口取得真实 STOP 证据，而不是删文件或伪造已停止。断电后的旧标定不可恢复，需重新读取四点。此轮是本地修复，不代表已完成 Git 推送、发布或安装包重建。
