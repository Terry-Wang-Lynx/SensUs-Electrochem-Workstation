## 2026-10-20 整机模型纠正

用户指出旧视图不符合 Fusion 设计。此前“模拟流程通过”没有验证整机运动拓扑，旧视图把 Z 组件错误地挂在 X 移动组下。已改为直接加载保存的 Fusion 整机和后续夹具 STEP 网格，X 只移托盘/孔板、Z 背架固定，详见 [模型来源](AUTOMATION-MODEL-SOURCES.md)。

新验证：848 项主机测试通过，含几何/前端专项 17 项；独立审阅逐一对比 108 个网格与对应 STEP 实体的包围盒、体积和平移，零不一致，6 份机械输入哈希未变。验证 96 孔对位和 X/Z 分组；浏览器加载正确整机、换列动画移动孔板，控制台无 error。没有改 Fusion 原文件或执行真实运动。新证据目录 `artifacts/automation-model-correction/`；下方旧版页面验证保留为历史，不再作为旧机构示意正确的依据。

## 独立审阅修正

发现并用回归测试修复：

1. 断开总线忽略未确认 STOP：现在保留连接、资源占用和恢复状态，重启也不能把它当安全空闲。
2. 磁盘满/日志写失败中断清理：各板终止和运动 STOP 分别尝试，审计失败显式标错，不宣称数据完整。
3. 等待动作改写列身份：禁止非移动等待指定新列，驻留列身份与已定位列一致。
4. 恢复状态的连接按钮误禁用：只开放必要的只读重连，参考/使能/运行仍受限。
5. 3D 预览忽略 X 覆盖：采用编译后的实际目标坐标，不再固定按 9 mm 列距移动示意。

另修复队列中的旧测量任务在获取锁后必须重查自动化占用、HTTP 异常统一机器可读格式、源码包漏带 JSON 示例。失败用例先观察失败，再验证修正。

后台 J-Link 序号来自操作系统枚举/缓存；BLE 模式旧文案“正在核对目标板”不表示已执行 SWD。审阅确认自动化占用期间设备发现受互斥，状态接口仅读状态与本地数据。

## 未验证与限制

- 本轮没有真实滑台连接、使能、回零或位移，也没有双板联合实测。机构方向/导程/行程/限位/碰撞、Emm 固件应答设置须现场核实。
- 软停不等于安全认证急停。电脑/总线/供电故障可能使设备无法接收 STOP，必须保留物理停机手段。
- 两板仅软件启动门禁，非硬件同步。模拟每阶段只生成少量演示点，不仿真真实采样率和电流精度。
- 已知 V5.2 第三路模拟异常未解决；本轮没有校准或精度签核。
- “指纹”目前为溯源 SHA256，不是尚未定义的电化学特征算法。3D 是 CAD 网格/机构示意，不是 3DGS 重建。
- 本地目录 `artifacts/` 不进入 Git；数据证据位于 `api-smoke.json` 指向的 run 目录。页面截图为 `high-throughput.jpg` 和 `apparatus-editor.jpg`。

接口及示例见 [AUTOMATION-API-v1.md](AUTOMATION-API-v1.md)。历史单板 BLE 实测另见 [VALIDATION-0.5.0.md](VALIDATION-0.5.0.md)，不得将其解释为本轮双板/双轴验收。
