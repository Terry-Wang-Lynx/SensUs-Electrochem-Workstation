# 同次上电四点实验标定

**当前已用[键盘对位](KEYBOARD-ALIGNMENT.md)替代手拧/松轴**。仍是一次上电内四个实验点，但普通入口保持锁轴、显式确认后只在标定时开放方向键/WASD；完成不再重新锁轴。下文松轴流程为历史兼容，不作为当前普通页指导。

2026-10-23，替代普通页独立机械四极限与额外CAD配准流程。仍是0.5.0本地开发版，未发布。

## 实验人员流程

1. 连接共享RS485的X1/Z2，保持电机电源和当前连接，不通过断电来松轴。
2. 确认Z有可靠支撑、松轴后不会下滑，勾选两项确认并点击“开始标定并松轴”。只发失能，不回零、清零或移动。
3. 手工对位并停稳，分别读取四点：物理第1列X、物理第12列X、浸入工作Z、提出安全Z。顺序不限；横向移动前先手动提出Z，避免拖碰管壁。第1/12列只确定X，不再用首点的Z代替独立工作高度。
4. 点击“完成并原位锁轴”。两轴控制器的目标位置0x33与实时设定目标0x34必须连续两次接近当前实读位置，才允许F3使能；否则保持受阻，不发位移、回零、清零或零脉冲来试探。点位保留，不把失败当完成。
5. 同一可信连接内复用这一次标定。正常STOP后，重新运行会只读核对原锁轴授权、目标/位置及完整配置，不自动发送F3。电机断电、连接变化或身份/基准变化后重新标定，不混用计数。

普通页不再要求另外读取X左右机械极限、Z上下机械极限，也不要求填写CAD坐标。旧限位/端点接口与数据只作历史兼容，普通页隐藏，不授权新的实物运动。旧三点标定可查看/模拟，不能替代本次四点标定。

## 保护与显示

- 实物运动只接受服务端以当前可信四点编译的模板；任意动作JSON不能自报标定ID绕过。原始API仍可模拟及进行不含运动的采集。
- X计划范围由第1/12列确定，Z由工作/安全高度确定。整计划、每条请求/量化目标和移动中的两轴反馈均检查；量化必要时向范围内取整，最多产生一个脉冲的内侧差异，不向外扩目标。
- 启动、每条运动及运动轮询均新读完整驱动profile；改变细分/方向/导程等后不能使用旧值。等待/采集也持续监测，异常请求停止并保留未知STOP，不据已连接串口宣布安全。
- 软件实验窗口不是硬限位或机械碰撞保证；掉电、电脑/驱动故障、惯性仍需要独立硬件保护。
- 完成的四点自动供3D使用，不另做第二套标定。X必须匹配CAD的有方向99mm孔列跨度，不缩放模型；Z把手工浸入点作为名义CAD工作姿态，保持导程1mm:1mm，画面注明Z姿态为示意，不当液位/浸入深度精度验收。
- 保存完整四点记录到每次真实运行目录`motion-calibration.json`并纳入manifest SHA，独立记录各阶段通信与采集溯源。

## 接口

前缀`/api/automation/v1`：

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `guided` | 四点要求、保存标定、当前手工流程；仅缓存 |
| POST | `guided/calibration/begin` | `{release_confirmed:true,z_supported:true}`，必须是布尔true |
| POST | `guided/calibration/capture` | `{point:"first"或"last"或"working"或"safe"}`，只读取，不接收客户端计数 |
| POST | `guided/calibration/finish` | `{}`，显式请求受目标寄存器门禁保护的原位锁轴 |
| POST | `guided/calibration/cancel` | `{}`，同样不能跳过安全锁轴条件 |
| GET | `devices`、`twin` | 缓存状态及自动四点显示；不读物理设备 |

连接UUID、完整机械/驱动配置与软件参考均须匹配。重启APP虽不主动清零电机，但新连接不能自动证明期间未断电，所以本版保守要求重新确认本次标定。

## 实物与验证边界

用户明确Z已支撑或不会下滑并授权松轴。根代理实际仅发送F3失能，两轴均回读失能/0RPM/status02，之后一直只读，没有发送F3使能、FD位移、回零、清零或配置写。手拧的编码器计数可变化，不能套用旧端点。

首次松轴后的旧版关闭逻辑把FE返回E2当未知STOP，原始失败保留在`artifacts/20261023-powered-manual-release/`。新实现只在明确E2且两次新鲜、健康、失能、静止反馈时接受`stop_basis:disabled_feedback`，`stop_acknowledged:false`；不是伪造STOP ACK。旧后台因此不能正常退出，核实双轴失能与0RPM后仅退出本任务创建的旧进程；更新后台后正常恢复失能停止确认并进入四点流程，日志见`artifacts/single-session-four-point-20261023/`。

当前真实流程已开始、两轴仍松开、四个实验点均未读取，尚无真实完成锁轴或完整实验验收。目标寄存器若在手拧后仍指向旧位置，完成会被有意阻止；手册没有无条件保证原位锁定，不能把离线替身通过当成实际锁轴通过。

验证包括驱动/模型/GUI/API回归、独立审阅及真实失能读取。两项审阅发现已修复：无独立限位时丢失运动中的双轴监测，以及缓存profile掩盖驱动细分变化。重复两次模拟实机串口替身运行验证同标定复用、无额外F3；没有在实物上自动移动。回归与源码包核对记录在同一证据目录。
