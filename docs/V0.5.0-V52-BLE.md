# 0.5.0 — V5.2 蓝牙接入

2026-10-19，本地开发版。未推送、打标签或创建GitHub Release。保留V4/J-Link RTT和V5.1/USB原有功能；新增MAX30134四通道V5.2。

## 使用

1. 给已安装`v52-0.1`蓝牙固件的板卡供电。设备广播名为`pA-V5.2`；本功能不负责给空片烧录或升级V5.2。
2. 启动工作站，点击“选择设备”→“扫描蓝牙”→“连接并验证”。若有多个板，按地址选择；扫描结果不等于协议已核实。
3. 选择工作区/批次。方法页选择分析通道CH1–CH4、恒电位、WE电位、DC量程/偏置和周期，再点“应用条件”。此操作通过蓝牙停止并配置，不会执行J-Link烧录。
4. 从样品页开始测量。四路始终同时采集；主图、稳态统计、标定与预测只使用所选通道。切换通道或板型会使旧标定不匹配，需要对应的新批次/标定。
5. 正常结束会发送STOP并核对确认。意外断线时，本轮失败但保留文件；板端可能仍在采样。重连后可在设备窗口点“停止板端采样”，或明确开始新一轮（先STOP、重新配置）。没有断线历史补传。

默认V5.2条件为WE=0.4V、WE−RE=−0.2V、50nA FSR、20%offset、PERIOD0，四路共用这组设置。DAC步进375µV，0.4V请求实际为0.400125V；设置回读保留请求/实际值。固定偏置是10/20/40/80nA，不是旧MAX30131的9/19nA。

V5.2仅支持恒电位I-t，不支持CV/EIS宽电流档、预阶跃、运行中切档、旧GET/SET硬件DEBUG、蓝牙固件升级。工作站软件更新按钮仍可用，它不是板卡OTA。

## 数据和分析

- `*-raw.csv`：选定分析通道的原始投影，保留板端全局序号。正常序号跨4不是丢样，不应用旧单通道连续序号检查。
- `*-all-channels.csv`：四路原始样本，含主机时间、板端时间、全局seq、channel、counts、整数fA和原始flags。
- `*-monitor.csv`：VDD/TEMP及四路WE/RE/CE，共14种监测量；电压µV，温度milli°C。
- `*.csv`、`*-filtered.csv`：现有分析导出/滤波派生数据；可能按配置输出频率重采样。它们不是额外硬件采样点，原始文件不会被改写。
- 运行目录保留原始通知、配置/停机审计、`ble-settings.json`和原子更新的`ble-state.json`。工作区导出保留全部通道、监测、`*-ble-state.json`及`*-ble-audit.jsonl`侧文件。

电流正方向为从WE流出，1nA=1000000fA。flags bit0表示饱和、bit1表示FIFO溢出、bit2表示未校准；正常flags=4不是坏点。禁止直接套用旧`analyze.py`可选counts重算的反向公式。原始及分析电流目前均是名义换算，不代表已校准准确度。

## 开发启动

```sh
make install
.venv/bin/python -m pa_host.gui_server --transport ble --port 8768 --open-browser
```

首次使用时允许操作系统蓝牙访问；无需浏览器Web Bluetooth授权。macOS原生App已加入蓝牙用途说明，源码依赖包含Bleak；冻结入口包含`collect-ble`及对应模块。`make app`是依赖本仓库`.venv`的开发应用，不是可移到别台电脑的自包含安装包。

```sh
make test
make app
.venv/bin/python -m build
```

0.5.0没有新增V5.2固件镜像。既有V4/V5.1随包固件保持不变，不能烧给V5.2。依赖锁中已包含Bleak3.0.2；未为本功能无关升级整份冻结依赖。

工作站界面完成了扫描、协议核对、应用条件、10秒四路采集、选中通道分析和文件导出；第二次集成测试四路各80条、共320条，板端序号400…719连续，选中CH1文件80条，STOP已确认。原始证据在本地忽略目录`artifacts/v050-validation/state/gui_runs/it_20261019_224139/`及对应workspace。
