# 四点标定的完成位置与实验范围

2026-10-24 的实物错误为 `travel_limit: Z keyboard reference is outside the verified coordinate extent`。安全 Z 记录计数为 1030585，完成时新鲜 Z 计数为 442205；按既有 2 mm/转换算，当前位置比已记录安全高度又高约 17.96 mm。旧实现只用四个记录点向外留 1 mm 建立正坐标容器，因此完成位置被算成负坐标，并错误触发硬故障。并非完成按钮应限制用户必须停在某个采点位置。

## 坐标与授权分离

- 完成前保持锁轴、冻结输入，读取新鲜双轴静止位置；坐标容器包含四个记录点和这次完成位置，再向两侧留已有虚拟参考余量。不发送位移、使能、回零或清零。
- 新记录的不可变 `completion_raw_counts` 保存坐标原点的证据。保存验证同时检查该证据和四点；正常实验末尾的可变 `reference.raw_counts` 检查点不会改写原点证据。历史无该字段的记录仍按原规则读取。
- 实验目标仍严格在物理第 1 / 12 列 X、工作 Z / 安全 Z 定义的范围内，容器扩大不授予额外横移、下探或采集权限。
- 完成前的纯几何/数据验证错误保留四点、原会话和可编辑状态；真实串口、身份、目标或停止异常仍封锁并停止。

## 从采集高度区间外的完成位置启动

只在本次连接、完整驱动身份及参考匹配、双轴新鲜静止，且实际位置匹配不可变完成位置时，可安装一次性的启动接近许可。X 必须已经位于标定的列区间内，Z 只能沿已观察的起始高度至记录安全高度的闭区间运动。完成位置高于安全 Z 时先到安全 Z；完成位置低于工作 Z 时，只允许向上提至安全 Z，不能进一步下探。该闭区间不授予后续普通实验目标额外权限。

真实计划第一步必须是编译器生成的 `move_z / safe_before_x`，目标必须正好是记录的安全 Z。不能先横移、等待、采集或直接到工作高度。安装或完成标定本身不运动；只有用户开始实物实验时才执行计划。

有限运动期间继续仅轮询活动 Z，确认 FE 停稳后撤销一次性许可，再按普通严格双轴范围与配置复核；之后才能横移、浸入或采集。STOP、故障、参考变更和断线均撤销许可。可选独立绝对边界仍生效，实验 JSON 不能打开或扩大该许可。X 在列区间外或位置不匹配时，不做自动找路。

第二次现场完成位置计数为 2046655、工作 Z 为 1932537，即比工作位置深约 3.48 mm。第一版启动接近仅处理安全 Z 上方，漏掉了正常向上提拉的情况，导致 `guided/run` 预检抛出 `invalid_request / Z feedback left the four-point experiment window`。现有回归通过真实 API 调用路径覆盖两侧起始位置、不同导程、首个 Z 停止后再验证 X/双板采集，以及预检停止不确认时保留控制器所有权和原始错误字节；不会把预检停止未知当成空闲。

## 证据

`artifacts/calibration-z-extent-20261024/` 保存实际四点、完成位置、错误日志及回归结果。专项使用真实标定服务、驱动和控制器对象，覆盖实际数据、四个方向的坐标容纳、保存重载、原点证据与检查点、启动首步约束、漂移/越界、身份/新鲜度、STOP 撤销及绝对边界。离线通过不代表完整双板双轴实物实验已验收。

原旧后台已把该现场会话判成硬故障，更新时不把备份 JSON 当成新连接的标定授权；当前点位保留供排查，新连接仍需显式四点标定。
