# 绝对运行限位：手工对位、四边界读取

2026-10-23开发增量。该功能是独立于孔板对位的运行约束，不是机械回零，也不是已验证的断电绝对定位。

## 操作

1. 在高级设置连接正确的X/Z共享RS485总线；连接只读，不自动松轴或运动。
2. 展开高通量页的“绝对运行限位”，点击“开始限位标定”。此时其它实验、登记参考、使能及重新连接被锁定，停止仍可用。
3. 人工完成安全对位，依次将机构置于已预留停止距离的X最左、X最右、Z最高、Z最低运行边界，分别点击对应的读取按钮。顺序可调整，四点必须来自同一连接。
4. 四点齐全且方向/跨度、位置与驱动配置均有效后，勾选“已留安全余量，未把机械硬挡作为运行边界”，再保存。
5. 然后进行孔板第1/12列及Z工作/安全高度对位；绝对限位独立保存，实验参数不能扩大它。

不要为了读取边界去撞机械硬挡。软件不提供自动找边、自动释放或回零。此前手拧后重新使能能否原位锁定仍未实物确认，原有门禁不会被本功能绕过。

## 实际保护

- X左/右及Z上/下保存为原始编码器计数和精确总线、轴机械配置、驱动配置/电源标志及连接身份。只修改软件参考点不能扩大原始边界。
- 启动真实实验前检查整条计划；发送每条运动指令前再次检查请求目标、脉冲量化目标和到位容差余量。靠边的请求可能被保守拒绝，不把到位误差视作越界许可。
- 驱动运动循环检查两轴位置；采集、驻留、等待/重连时控制器继续监测。越界或位置读失败请求停止，保留错误、日志和未确认停止的资源所有权，不自动恢复。
- 普通确认STOP不改变原始坐标，已装载边界在同一可信连接上保留。断开重连、驱动配置/已知位置基准变化或保存记录损坏时不能继续套用；记录保留显示，但需要重新读取四边界。
- 缺少有效绝对限位时，工作站的旧动作API、新模板及其它真实运动均被拒绝。模拟仍可使用；模拟几何不作为真实限位。

## 能力边界

**纯上位机无法保证通信中断、电脑失效、驱动失控或惯性下物理上绝不越界。** 本功能不能替代独立硬限位开关、硬件急停和留足停止距离的机械设计。“绝对”指不可被实验覆盖的运行边界，不表示已验证断电位置仍可信。

本轮开发测试不连接或操作实物；不会代替用户读取四个真实位置。X/Z当前停留位置保持此前人工观察的终点，不能把现有位置或CAD范围自动当作限位。

## Agent API

前缀 `/api/automation/v1`：

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/limits` | 当前状态、保存记录、读取草稿及错误；不读取物理设备 |
| POST | `/limits/begin` | 开始独占读取流程，空请求体 |
| POST | `/limits/capture` | `{boundary:"x_left"}`，其它值为`x_right`、`z_up`、`z_down` |
| POST | `/limits/save` | `{clearance_confirmed:true}`；必须为JSON布尔true |
| POST | `/limits/cancel` | 取消读取，不移动，不恢复旧目标 |
| POST | `/stop` | 始终可请求停止；不伪造已确认结果 |

客户端不能提交`raw_counts`、任意`bounds`或关闭门禁。所有边界来自服务端静止读取。记录保存在自动化状态目录的`absolute-motion-limits.json`，不嵌入可编辑实验JSON。

浏览器验证四按钮、未连接禁用提示和模拟可用；HTTP验证缺省未标定、禁止客户端注入计数、未连接不开始标定且不创建串口连接；当前模拟无真实限位也能完成物理第7列示意，并且不生成“已执行限位”的记录或指纹。

证据：`artifacts/absolute-limits-validation-20261023/`，包含`pytest-final.txt`、`http-smoke.json`、`simulation-smoke.json`、浏览器截图和仅串口替身生成的`offline-flow-data/`。严格运行日志中的`absolute-motion-limits.json`保存该次真正使用的边界，后续重标定不改旧运行记录，manifest负责文件SHA。替身数据的`mode:live`只表示覆盖控制器真实分支，不代表实物验收。

本轮没有连接/移动实物，没有自动释放/使能/回零，也没有写板端固件；不声称机械防撞、停止距离或双板双轴现场验收通过。四个真实边界仍等待用户现场对位读取。
