**Goal:** Existing workstation gains a verified V5.2 BLE four-channel I-t path without regressions to V4/V5.1.
**Architecture:** Explicit BLE device branch, separate async NUS module/collector process, selected-channel projection into existing analysis, four-channel sidecar visualization.
**Tech Stack:** Python, Bleak3, local HTTP server, vanillaJS/canvas, pytest.
**Spec:** `docs/superpowers/specs/2026-10-19-v050-v52-ble.md`

## Global Constraints

- No legacy firmware fallback/flash for BLE; no firmware or hardware edits.
- Preserve units/sign/flags, global sequence and board/channel calibration identity.
- Explicit scan only; never take a second connection during acquisition.
- STOP acknowledgment before success; disconnect/no-data/overflow/config mismatch must fail closed and preserve files.
- No automatic release/push/tag; macOS real-board test only, Windows support not claimed tested.

## Review Focus

- Missing/wrong STATUS despite successful ACK; nonmatching run token.
- START/STOP timeout, disconnect and user-stop during startup.
- Interleaved four-channel samples, overflow flags, unknown/oversize protocol frames.
- Legacy auto-flash fallthrough or changed legacy defaults.
- Calibration model reused across channel/board and missing frozen BLE packaging support.

### Task 1: NUS adapter and four-channel collector (transport worker)

Files: create `software/host/pa_host/v52_ble.py`, `collect_ble.py`, `software/host/tests/test_v52_ble.py`, `test_collect_ble.py` only.

Interfaces: synchronous `scan_devices(timeout=4.0)->list[dict]`, `probe_device(address)->dict`, `configure_device(address, settings)->dict`, `stop_device(address)->dict`; pure `validate_settings(settings)->dict` returns V5.2 fields/settings preserving caller's common keys. Async session helpers are internal. Device rows include id=`ble:<address>`, kind/transport=`ble`, address/name/rssi, board_profile=`v52`, selectable=true. `configure_device` returns INFO/complete parsed STATUS and requested/actual DAC details.

Collector CLI: `--address --settings <json> --out <selected raw> --all-channels <csv> --monitor <csv> --audit <jsonl> --raw-log <text> --cmd-file <text> --state-file <json> --run-token <token>`; settings include duration_s, adaptive_stop, analysis_channel. Output selected CSV uses record.CSV_COLUMNS, global seq, sat=flags&1, ovf=flags>>1&1, no fabricated firmware epoch. Sidecar all-channel header includes host_unix_s,seq,dev_ms,channel,counts,fa_fw,flags. Monitor header host_unix_s,quantity,channel,counts,value,flags,unit. Atomic state JSON includes run_token, phase=configuring/running/completed/stopped/error, config_confirmed, config details, error, stop_confirmed. Exit0 normal duration+STOP;3 explicit STOP+ACK;1 failure. Read only STOP from command file. Writes config_confirmed before START only after complete STATUS comparison, and data capture begins only after clean current-session startup. Signal/timeout cleanup attempts STOP with bounded timeout, never reports successful stop without ACK.
