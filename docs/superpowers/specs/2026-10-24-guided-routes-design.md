## 用户需求与待确认项

用户需要保留既有勾选列流程，同时支持 `1,3,5,7,9` 整轮重复三遍，以及 `1,3,5,7,9,7,5,4,3,1` 这样的有序、可回访路径。顶部应有显著的大进度条及预计剩余时间。

已向用户提出统一模型：路径独立于执行次数；模式为一次、重复 N 轮、无限循环。无限表示重复当前路径直到手动停止，等待用户确认这一定义。确认之前不修改产品代码。

## 操作语义

- 路径来源为“已勾选列，按物理列号顺序”或“自定义列序列”；序列不得排序、去重或压缩物理间距。
- 一轮指完整执行一次路径，而不是一列。重复三轮就是执行原路径三遍；只有还有下一轮时才返回路径首列。最后一轮末列结束后抬到安全高度，不自动返回。
- 每次访问某列都执行既有安全抬升 / 横移 / 浸入 / 停稳 / START 与采样 / 停止采集 / 提出的完整流程。每列沿用自身已保存的名称、时长和 A–H 有效窗口，不覆盖现有 5 秒设置。
- 重复访问同一列也单独记录一次访问及样本；通过运行、轮次、路径位置、累计访问号、物理列号和唯一动作号区分。
- 用户暂停仍在当前列完成并抬起后生效，包含轮次交界处。STOP 仍按既有真正双轴停止与板输出确认处理，未知 STOP 保留资源所有权。
- 不提供自动回零、断电续跑、自动复用旧连接标定或无确认实物启动。所有真实运动仍受本连接四点范围及现有逐步反馈检查约束。

## 文档及接口

- 既有 `guided-1.0` 文档完全保持原有含义；无执行扩展就是一次执行全部勾选列。
- 新功能使用 `guided-1.1`，新增 `execution: {mode, count, route}`。`mode` 为 `once` / `repeat` / `infinite`；`once` 的 count 为 1，`repeat` 为 1–500 的整数，`infinite` 为 null。`route: null` 代表勾选列的物理顺序；数组代表明确的列序列。
- 自定义数组非空、只含 1–12 的整数，保留重复。数组中的列必须为已启用列。界面应用自定义路径时明确同步启用其中的列，不能悄悄跳过路径项。
- 保存、预览、运行仍使用现有 Agent API；扩展进入完整文档 / 计划指纹。不可让仅修改路径或模式沿用旧预览或旧幂等运行。
- 服务端编译一轮有限、已验证的动作计划，通过受控循环延迟生成各轮独立动作号。每轮保持现有 500 展开动作和八小时估计上限；有限实验总估计和运行仍不超过八小时。
- 明确选择 infinite 才不施加整次八小时自动结束时间；单次运动、板 START/STOP、事务、采集窗口和取消保护仍各自有截止时间。磁盘 / 审计失败或通信、范围保护仍会终止无限实验，不是无限制绕过保护。
- 状态及 manifest 新增执行策略和进度字段；无限循环不在内存预展开、不无限累积计划或访问历史。长期原始数据照常追加落盘，内存事件 / 曲线继续使用现有有界缓存。

## 顶部进度

- 进度必须来自已启动运行快照，不从正在编辑的模板反推。
- 有限模式显示总体百分比、当前轮次 / 总轮次、当前路径位置 / 本轮访问数、物理列、已用时间、预计剩余时间。只有成功结束才显示完成 100%。
- 无限模式显示“持续循环，无总结束时间”、已完成轮次及当前轮进度；总体百分比和总剩余时间为 null，不能伪造有限终点。
- 估计包含顺序路径移动、升降、稳定等待、采集时长，以及轮次之间从末列到首列的安全返回距离；启动时以真实已读位置为初始坐标，模拟使用模拟坐标。
- START 未确认时不把采集时间当已完成；暂停 / 等待人工或设备恢复时显示剩余估计暂停或待恢复，不继续假倒数。正常运动时以实际完成动作与当前动作的估计进展显示，标注预计值不等于精确完成承诺。

## 实现与验收边界

继续使用现有 Python 服务与原生 JS/CSS，不新增前端框架、3D 或运动驱动依赖。不修改电机协议、板端固件、采样映射、既有自然到位无 FE 策略和正常停泊证明。

离线测试覆盖旧模板兼容、路径顺序与重复、三轮返回、任意首列、同列连续回访、参数 / 标定不变、唯一数据目录、无限循环有界 / STOP / 轮末暂停、故障与未知 STOP、START 门禁、暂停 ETA、总体完成显示和忙时编辑阻断。HTTP 模拟及浏览器显示验证不发实物运动或板端 START。双板双轴自定义重复实物验收仍另列，不把模拟当作实测通过。
