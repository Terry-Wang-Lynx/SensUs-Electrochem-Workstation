## 实板

目标为nRF52833/MAX30134，MCU `2AB09D3A/5CB8FDA6`，蓝牙名`pA-V5.2`，固件`v52-0.1`、ID34/rev84。未在本轮修改或重新烧录板端固件。四组电极悬空，所有工作区均为隔离的smoke测试目录，不是校准数据。

- GUI实际完成扫描→协议验证→应用条件→10秒采集→保存/分析：每通道80条，合计320条；选CH1投影80条，seq400…719，STOP确认。
- 切换CH2后界面明确提示与CH1标定不匹配。独立工作区的第二轮接口实测同为每通道80条、合计320条，选中通道投影80条；原始、全通道、监测、状态、审计均导出，STOP确认。
- 第二轮CH2末端稳定窗口不足，界面未产生有效稳态值/标定候选；这是既有质量门禁，不能把“采集完成”解释成“可用于标定”。
- 主界面与悬浮窗均展示CH2身份/未校准说明；四路面板图形和电压/温度单位已检查，过期监测明确标记旧读数。最终布局实测workspaceBottom=332.65、bleTop=362.65，无重叠。
- 内置浏览器不支持旧版批次命名的prompt，并在切换目录confirm处出现控制超时；未为此次功能重写旧弹窗。第二轮目录/批次步骤通过同一后端HTTP接口完成，随后在新页面检查实际结果。不能将此步骤列为内置浏览器弹窗兼容通过。

## 本轮发现并修复

1. `--settings`文件路径与JSON正文接口不匹配：实际CLI文件回归红→绿，失败首轮未START且记录保留。
2. 窄窗口新增第三面板挤压旧网格：对可见BLE面板使用独立自动高度行，不用遮挡修补。
3. 界面错误声称“不重采样”：改为区分四路原始保存与选中通道的重采样分析导出。
4. 展示说明字段进入标定签名，导致同条件重启后不匹配：规范化设置白名单修复，并保留板型/通道隔离。
5. 自动检测回落RTT或BLE/旧板切换丢失V5.2通道设置：保存独立配置快照，切换仍要求重新应用。独立复审确认原CH4/−0.3V复现已修复。
